# 프로젝트 관제와 실시간 로그 적용 가이드

작성일: 2026-10-06

## 중앙 Agent

공개 샘플의 `public` 소스를 빌드하여 중앙 Agent를 재배포한다. 신규 Flyway `V19`가 XLog·실시간 로그 메뉴와 기존 역할의 권한을 추가한다. 적용된 V18은 변경하지 않는다. 기존 연결은 중앙 재기동으로 끊기므로 사용자가 인스턴스에서 연결 시작을 다시 요청한다. 자동 재연결은 하지 않는다.

상단 프로젝트 선택은 관제 화면의 조회 범위다. 종합현황 최초 진입 시 조회 가능한 첫 프로젝트와 첫 인스턴스를 기본 선택한다. 유효한 URL 선택은 유지하며 프로젝트 변경 시 새 프로젝트의 첫 인스턴스로 전환한다. 프로젝트·인스턴스 드롭다운은 CMS 사이트 선택기와 같은 폭 160px·높이 24px로 구성한다. 펼친 목록에서 프로젝트명·ID 또는 인스턴스명·ID·환경·호스트를 검색한다.

종합현황은 선택한 인스턴스 한 대의 자원 이력만 조회한다. CPU·RAM·XLog·JVM Heap·디스크를 같은 차트 그리드에 배치하며 XLog 점은 2px다. XLog 카드는 최근 1시간, 자원 차트는 선택한 조회 기간을 사용한다. 실패 API·만료 예정 인증서 숫자는 같은 범위의 목록으로 이동한다. 사용자·역할·메뉴 설정은 전역 관리다.

## XLog

프로젝트 설정에서 XLog를 사용으로 설정하고 인스턴스의 웹소켓을 연결한다. 화면 진입만으로 연결하거나 XLog를 켜지 않는다. 종합현황과 XLog 메뉴에서 시간별 요청 응답시간 분포를 볼 수 있다. 가로축은 대상 WAS의 요청 시각, 세로축은 처리 시간(ms)이다. 청록색은 HTTP 2xx·3xx, 분홍색은 HTTP 4xx·5xx다. 점을 클릭하면 프로젝트·인스턴스·메서드·경로·시간·HTTP 결과를 표시한다.

차트는 확대·축소할 수 있다. 주기적인 갱신은 중앙 저장 이력을 읽으며 대상 WAS를 호출하지 않는다. 조회 기간은 최대 24시간, 차트와 목록은 페이지당 최대 1,000건이다. 이전 기록은 ID 커서로 조회한다. 수집 요청 수·오류 수·평균·P95는 해당 조건으로 중앙에 남아 있는 기록 전체를 집계한다. 보관 상한과 전송 버퍼 때문에 전체 서비스 트래픽 수나 완전한 TPS로 해석하지 않는다. SQL·메서드 추적은 제공하지 않는다.

## 실시간 로그

실시간 로그 메뉴에서 프로젝트·인스턴스·등록 파일을 선택하고 **조회 시작**을 누른다. 다음 조회부터 파일에 추가된 구간만 읽는다. 조회 주기는 로그 설정의 값을 사용하며 웹소켓에서도 동일하다. 화면을 숨기거나 이동하면 조회를 중단한다.

마지막 조회 시각이 바뀌면서 **새 로그 없음**이 표시되면 파일 읽기 요청은 성공했지만 추가된 내용이 없다는 뜻이다. 로그는 해당 파일에 실제로 쓰인 내용만 표시한다. Tomcat 시작·오류 로그에는 일반 페이지 접속마다 기록이 추가되지 않을 수 있다. 애플리케이션 로그와 접근 로그는 실제로 기록되는 파일을 등록해야 한다.

### 날짜별 로그

`catalina.2026-10-05.log`처럼 날짜를 고정하면 계속 그 파일만 읽는다. 날짜별 파일을 따라가려면 신규 Collector JAR을 적용한 뒤 아래처럼 등록한다.

```text
E:/web/apache-tomcat-8.5.61/logs/catalina.{yyyy-MM-dd}.log
```

날짜는 대상 WAS의 시간대를 사용한다. 자정 이후 새 날짜 파일이 아직 없으면 `LOG_FILE_UNAVAILABLE`이 표시된다. 파일이 생성된 뒤 조회를 재개한다. 다른 시간대의 날짜를 쓰는 애플리케이션은 실제 파일 명명 규칙과 일치해야 한다. 고정 파일은 기존 방식으로 동작한다.

Linux의 고정 출력 파일 예시는 다음과 같다.

```text
/usr/local/tomcat/logs/catalina.out
```

허용 폴더는 기존 프로젝트 properties의 `monitor.log.allowed-roots`에 설정한다. 날짜 대체 후에도 허용 경로·실제 경로·심볼릭 링크 검증을 수행한다. 한 번에 읽는 최대 크기는 128KiB다. 웹소켓에서 경로·권한 오류를 반환할 때 실제 경로·예외 메시지 대신 안전한 오류 코드만 노출한다.

## 대상 Collector 반영

화면 개편은 중앙 배포만 필요하다. 날짜별 파일 전환과 웹소켓 로그 오류 개선은 새 `collector-0.1.0-SNAPSHOT.jar`를 대상 앱의 `WEB-INF/lib`에 교체하고 WAS를 재기동해야 한다. 기존 설정·Configurer 공개 API는 유지한다. 프로젝트별 Java 코드와 web.xml을 다시 수정할 필요는 없다. 이름이 다른 구버전 Collector JAR을 동시에 남기지 않는다.

신규 JAR의 날짜 패턴 기능을 확인한 뒤 대시보드의 파일 경로를 수정한다. 구버전 JAR에서는 `{yyyy-MM-dd}`를 실제 파일명으로 인식하므로 경로 패턴을 먼저 적용하지 않는다.

## 검증 범위

자동 검증은 파일 추가 구간·커서·날짜 전환·허용 경로와 실제 웹소켓 로그 명령을 포함한다. 중앙 API는 PostgreSQL로 기간·경로·오류 집계·프로젝트 권한·메뉴 권한을 검증한다. UI는 범위 변경, 로그의 명시적 시작·일시정지·숨김 중단과 요청 정보 모달을 확인한다. 운영 WAS의 장기간 성능 검증 결과를 의미하지 않는다.

로컬 브라우저 검증은 가상 API 데이터로 다크·라이트 종합현황, XLog 요청 정보 모달, 모바일 배치와 가로 넘침을 확인한다. `/xlog`, `/logs`, `/instances` 직접 진입·새로고침도 중앙 라우팅 테스트에 포함한다. 가상 요청을 운영 XLog 데이터로 저장하거나 운영 설정을 변경하지 않는다.
