# 실시간 서버 로그

인스턴스 상세 → **실시간 로그** → **로그 등록**에서 이름, 대상 서버의 파일 절대 경로, 인코딩, 사용 여부, 조회 주기를 설정합니다. 기본 주기는 10초이며 5~1,800초(30분)까지 설정할 수 있습니다. 신규 로그는 미사용으로 시작합니다.

- **사용**: 로그 이름을 클릭해 화면을 열었을 때만 폴링합니다. 일시정지, 다른 탭·페이지 이동, 브라우저 탭 숨김 시 요청을 멈춥니다. 숨긴 브라우저 탭을 다시 표시하면 조회를 이어갑니다.
- **미사용**: 수동·자동 파일 읽기 모두 차단합니다. 프로젝트 또는 인스턴스가 미사용이어도 로그 읽기는 차단됩니다.
- 파일을 처음 열 때 최대 최근 200줄, 128 KiB 범위만 읽습니다. 이후 파일 커서 뒤에 추가된 바이트만 가져옵니다. 파일 교체·잘림을 감지하면 최근 내용으로 전환합니다. 아주 긴 줄·대량 출력은 제한 범위만 표시합니다.
- 대시보드는 최대 2,000줄/128 Ki 문자만 표시합니다. 새 로그가 없는 경우 빈 응답을 받습니다. WebSocket을 사용하지 않습니다.
- 대상 서버의 기존 로그를 그대로 읽습니다. 전용 로그 생성, 로그 설정 수정, SMS 발송, API 점검 실행은 하지 않습니다. 파일 원문은 가리지 않으며 HTML로 실행하지 않습니다.
- 로그 본문을 DB나 파일에 저장하지 않습니다. 여러 조회자가 같은 파일을 열면 Agent 서버가 주기당 한 번 읽은 결과를 공유합니다. 임시 버퍼는 최대 64개/각 128 Ki 문자이고, 5분 동안 요청이 없는 버퍼는 1분 간격 정리 작업에서 제거됩니다. Agent 서버 재시작 시 사라집니다.
- 관리자와 해당 프로젝트의 운영자만 조회·설정할 수 있습니다. 조회자는 로그에 접근할 수 없습니다. 조회 시작 이력에는 사용자·시각·프로젝트·인스턴스·로그 ID만 저장합니다. 설정 변경 이력에는 파일 경로와 설정값이 포함됩니다. 토큰·로그 원문·파일 커서는 이력에 저장하지 않습니다.
- Collector는 로그 읽기를 최대 1개, Agent 서버는 최대 4개까지 동시에 처리합니다. 자원 수집·API 점검 실행기에 로그 요청을 넣지 않습니다. HTTP 오류·권한 오류·타임아웃이 발생하면 화면의 자동 조회를 중단하고, 서버에서도 같은 파일 요청을 최소 60초 쉬도록 합니다. 파일 접근 정책과 `/monitor/v1/*` 경로의 방화벽/WAF 허용은 대상 서버 담당자와 조율해야 합니다.

## 대상 서버에 반영할 파일

1. `WEB-INF/lib/collector-0.1.0-SNAPSHOT.jar`를 새 JAR로 교체합니다. Java 7 바이트코드 및 Java 7 API 호환을 검증합니다. 기존 자원·API 모니터링 설정과 프로젝트의 Configurer 자바 클래스는 그대로 사용합니다.
2. 기존 `WEB-INF/web.xml`의 **monitor servlet 선언 안에** 아래 `init-param`만 추가합니다. 기존 전체 web.xml을 교체하지 마세요.
3. WAS를 재기동합니다. JAR 교체만으로는 기존 로딩 클래스가 바뀌지 않습니다.

Sample의 실제 로그가 `/usr/local/tomcat/logs/catalina.out`인 Linux 서버 예시:

```xml
<init-param>
  <param-name>logAllowedRoots</param-name>
  <param-value>/usr/local/tomcat/logs</param-value>
</init-param>
```

대시보드의 파일 경로에는 `/usr/local/tomcat/logs/catalina.out`을 등록합니다. 컨테이너에서는 **Collector가 실행되는 컨테이너 안에서 보이는 경로**를 사용합니다.

Windows는 실제 Tomcat 로그 폴더의 절대 경로를 같은 `param-value`에 넣습니다. 여러 허용 폴더는 세미콜론(`;`)으로 구분합니다. 샘플 대학·샘플 기업의 웹앱 위치가 Tomcat 로그 위치를 뜻하지는 않으므로 실제 WAS 로그 경로를 확인한 뒤 지정해야 합니다. 전체 드라이브 대신 로그 폴더만 허용하세요.

허용 폴더를 절대 경로로 설정하지 않으면 `LOG_ROOTS_NOT_CONFIGURED`, 폴더 밖 경로는 `LOG_PATH_NOT_ALLOWED`로 차단합니다. 심볼릭 링크·상위 경로 이동도 최종 실제 경로를 검사합니다. 원격 UNC 공유 경로는 허용하지 않습니다. WAS 실행 계정에 파일 읽기 권한이 있어야 합니다. 허용 폴더 안에서 파일 추가·주기 변경·사용/미사용 변경은 대시보드만으로 처리하며 JAR 재배포가 필요 없습니다.

## Agent 서버 반영

Agent 서버를 빌드·재시작하면 V15 마이그레이션으로 로그 **설정** 테이블을 추가합니다. 기존 등록 프로젝트와 자원 기록은 유지합니다. 대상 서버에 이전 JAR가 남아 있어도 자원/API 모니터링은 유지되며 로그 요청만 실패합니다.

## Collector 요청 형식

`POST /monitor/v1/logs/read`, 기존 `X-Monitor-Token` 인증을 사용합니다. 요청에는 `path`, `encoding` (`UTF-8`, `MS949`, `EUC-KR`), `cursor`만 허용합니다. 처음에는 `cursor: null`, 다음에는 받은 커서를 사용합니다. 성공 응답에는 `text`, `cursor`, `reset`, `limited`, `identity`가 포함됩니다. 파일 읽기 실패는 HTTP 200 안의 `code`로 반환해 기존 서비스의 JSP 오류 페이지로 전달하지 않습니다. 인증 실패는 HTTP 401입니다. 로그 요청 본문은 최대 16 KiB입니다.

읽기는 제한된 파일 범위만 수행하지만 네트워크 파일 시스템 등의 파일 I/O가 OS에서 멈추는 상황에 강제 종료를 보장하지는 않습니다. 단일 읽기 슬롯으로 추가 작업이 쌓이지 않도록 제한합니다.
